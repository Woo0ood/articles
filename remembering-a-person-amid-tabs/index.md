一个人在浏览器里度过的时间，大概比在任何别的软件里都多。查资料、比价、订机票、半夜读完一篇长文、和 AI 来回聊上十几轮，都发生在同一个窗口里。可到了第二天，浏览器记得的只有一串网址。它知道你打开过哪些页面，却不知道你那三个晚上其实都在为同一趟旅行做攻略，更不知道你为什么最后放弃了那家酒店。

我们想让 Phi 记住的，是网址之上的那一层：你最近在忙什么、在意什么、习惯怎样做事。有了它，你问助手一个问题时，它不必从零开始认识你；打开一个新标签页，迎接你的也可以是一句真正和你有关的话。

这篇文章讲我们怎样搭起这套记忆，以及一路上慢慢形成的几条信念。它们大多不是一开始就想清楚的，而是在一次次试错中思考出来的。

## 记住的应该是关系

在设计 Memory 时，最直观的思路是建造一个更大的仓库：把用户看过的一切存下来，需要时再去检索。我们很快发现这条路走不通。一天里几百次点击和跳转，大多只是匆匆一瞥；真正要紧的东西往往藏在一连串看似无关的页面之间。

所以我们换了一个问法。与其问「这个人看过什么」，不如问「这个人和这些东西是什么关系」。同样是 React ，对一个人是每天的工作，对另一个人可能是周末想学的新东西。 Memory 里因此没有孤立的「世界知识」，只有以你为圆心展开的关系，每一条关系旁边都写着一句人能看懂的大白话：「在 Steam 上玩游戏」、「为工作读分布式系统的文章」。

这个选择之外，还有三件事我们始终在注意和避免：模型擅长讲故事，从零散的线索里推断「你是什么样的人」时，很容易说出证据并不支持的话。人会变，换了工作、改了口味，旧的事实应当被替换，而不是和新的并排躺着。还有最重要的，浏览记录、输入和截图是一个人最私密的数据，它们必须让用户随时看得见、自己可以修改、并且可以方便的删掉。后面几乎每一个设计，都是在回应这三件事。

浏览器这一端只负责看。看到的东西被送进一个运行在你自己电脑上的 Memory Service ，在那里一层层整理成记忆；任何服务想用它时，都只能经过同一个入口。每往上一层，记录就更抽象一些，但也都能顺着指针，找回下面那层的原始证据。哪怕把上面几层整个推倒，也能从底下重新算出来。

## 先学会看

Memory 从观察开始。 Phi 内置的一个扩展负责记下页面的加载、点击、滚动等动作，以及你在其他 AI 网站上问过的问题。它不保存，不分析，只负责把看到的东西稳妥地送走。

「看」也要有分寸。输入框只在你确认提交时记下最终的内容，而不是每敲一个字就记一笔；密码框里的字一律换成星号。每个网站都可以单独关掉记忆，关掉之后，那里发生的一切都不会被看见。当助手替你在网页上点点按按时，那些动作不是你做的，也不会被记成你的经历。

送的过程同样要保证稳定。所有事件先放进本地一个持久化的发件箱再成批送出。浏览器把后台挂起了、服务重启了，数据都还在。偶尔有一条格式坏掉的事件，它会被单独挑出来丢掉，不会把后面整支队伍都堵住。

## 从流水账到一条条线索

最初，我们把每一小批页面压成一段摘要，再让 LLM 判断它属于哪件事。每压缩一次都在丢东西：先后顺序没了，确切的时间没了，同一分钟里另一个标签页在做什么也没了。「过去半小时，你在同时忙哪几件事」，这样朴素的问题，系统竟然答不上来。

后来，我们把浏览当作一条「河」来对待。每个事件都带着你自己的时间、所在的标签页和窗口，被完整地留下来，任意一段时间都能原样铺开成一份按时间排列的「流水」。然后把「流水」切成一次次「访问」：同一个标签页停在同一个页面上的那一段，点了几次、输入了什么、停了多久，都由代码数清楚。只打开、没动过的页面先放一放，等它有了动静或者被关掉再说。

接下来只剩一个问题：这次访问属于一件正在进行的事，还是一件新事？回答它的是一个专门做判断的决策模型。它只能从选项里挑，并给出每个选项的概率。候选的事也只用代码生成的访问记录来描述，里面没有任何 LLM 自己写下的标题，所以它不会被自己上一次的措辞带偏。问一次就定下来而不是反复推翻。等结构确定下来，再让一个擅长写作的 LLM 给这件事起名、写一句摘要。它只写访问里看得见的东西，而不会神神叨叨的揣测动机。

## 一张以你为圆心的图

[![Memory Galaxy：以你为圆心的记忆关系图]({{ '/assets/images/remembering-a-person-amid-tabs/memory-galaxy.png' | relative_url }})]({{ '/assets/images/remembering-a-person-amid-tabs/memory-galaxy.png' | relative_url }})

在这些线索之上， Memory 分成三类：你做过什么； Phi 替你做过什么，你满不满意；以及关于你的、相对稳定的事实，比如你在哪里工作，偏爱什么。最后一类门槛最高，要足够确定才会留下，同一个网站能留下的「事实」有上限，新的事实会取代过时的，而不是与它并存。你在对话里一句话既交代了背景又提了问题，系统会把两者拆开分别记下；「再短一点」这样离开上下文就看不懂的碎片，会先结合前文补成完整的一句，补不完整就宁可不记。

再往上，是一张以你为圆心的关系图。圆心只有一个点 —— 就是你；第一圈是你接触过的人、地方、产品、网站和话题；第二圈是按时间排开的一件件事。一件事向内连着你，向外连着它碰到的东西，把「你、那个时刻、那些东西」联系在了一起。

这张图从不被直接改写。新的发现先以「提案」的形式出现：加一个点，连一条线，归档一个旧节点。大多数提案只是累加，不需要任何模型。只有可能冲突的那一小部分，比如「现在的男朋友」只能有一个 —— 才会被挑出来交给模型裁决。于是成本跟着冲突的多少走，而不是跟着记录的多少走。每一批改动连同它的来由，都被记进一本只增不减的账里。于是每一次变化都能原样摊开来看；当某个推断被推翻时，也能顺着推导链，把建立在它之上的结论一并撤回。

图里的每个点都记得自己从哪里来：是看到的，是你说的，还是推断出来的；把握有多大；依据是哪几条记录。发生冲突时，有一条不交给模型的底线：你亲口说的，胜过系统看到的；系统看到的，胜过它推出来的。哪怕是从你常用的网站导入的整整几年历史，也只算「看到的」，不会冒充「你说的」。

## 被看见的记忆

[![Nebula：从记忆中写给你的信]({{ '/assets/images/remembering-a-person-amid-tabs/nebula.png' | relative_url }})]({{ '/assets/images/remembering-a-person-amid-tabs/nebula.png' | relative_url }})

还有一个我们称为 Nebula （ Beta ） 的小小构想。

Nebula 是 Memory 写给你的信。在 Memory 的世界里，记忆并不是一个个孤立的片段。你说过的话、经历过的事情、某一刻的情绪、正在追寻的目标，以及那些不经意间流露出的想法，都在彼此之间建立着联系。它们随着时间不断生长、交织，逐渐形成一个独属于你的记忆宇宙。

Nebula 会从这个宇宙中寻找那些仍然活跃的记忆，理解它们之间的关联，梳理事件的发展与变化，发现一些可能连你自己都未曾留意的线索。它不只是回顾过去发生了什么，更尝试理解这些事情对现在的你意味着什么。

这些记忆最终会化作一封封独属于你的信。它们或许会写到你最近生活中的变化，或许会重新拾起一个尚未完成的愿望，也或许会将相隔很久的两段经历联系起来，为你提供一个重新认识自己的视角。每一封信都源于真实的记忆，却不止于记忆本身。

我们希望 Memory 不仅能够记住你，也能够让记忆产生新的意义。那些曾经散落在时间里的片段，终有机会以另一种方式重新来到你的面前。

这就是 Nebula 。它不是一份关于你的记录，而是从你的记忆深处，寄给此刻的你的一封信。

## 在对话里想起

当你和 Phi 聊天时，它脑子里有你的画像、你最近在做的事、它以前替你做过的事。遇到需要回忆的问题，它先看一眼记忆的目录：每一行是一样东西，写着它的类别、名字、相关的记录有多少、最近一次是什么时候。看过目录，它才决定要不要继续查找，应该查询什么。

真正去查询时，它先按语义找出候选。拿回来的不是一句笼统的总结，而是一样样具体的东西：它是什么，你和它是什么关系，最近几次相关的经历，当时打开的是哪个页面。然后决策模型会对每一样东西问同一个问题：它对回答眼前这个问题有没有帮助？只有足够可能有帮助的才会留下。这一步只做减法，所以一旦它超时或出错，所有证据都会原样保留。 Memory 在这里是配角，就算配角出了状况，戏还是要唱下去的：假如 Memory Service 瓜了的话，对话还是会照常进行，只是少了一些对你的了解。

还有一种错误藏得很深。你刚问过「我喜欢喝什么饮料」，这句话会被记进记忆。可如果下一秒它又被当成「你浏览过的证据」翻出来，助手就会拿你的问题来回答你的问题。所以一段对话里写下的东西，不会在这段对话里回流；来自对话的记录，也总会被标明是「你以前问过」，而不是「你以前看过」。

一个人常常不止一个浏览器 Profile ，工作一个，生活一个。每个 Profile 是一份独立的记忆。回忆时可以把它们合在一起读，每条证据都注明来自哪一个 Profile ；写入时则永远只落进其中确定的一个。

Phi 也记得它自己是谁。它有一份不变的底色，一段慢慢积累的自我叙述，以及你对它的长期要求，比如「以后回答幽默一点」。这份自我认识在每一次对话开始时被放在最前面；每天，它还会安静地自我反思一次，沉淀所有关于你的记忆，写到自己的记录中。

## 写在最后

回头看，这套系统里最要紧的，并不是某个模型或某张表，而是几条一再被验证的分寸。记关系，而不是记网址。每一个结论都能找回它的证据。你说的话，永远排在推断之前。代码、判断和写作各做各的事。记忆出了问题，就安静地退到一边。以及， Memory 始终属于你，它永远只存储在你的设备上，绝不会在云端进行持久存储。

浏览器记住的，终究不是一个人的全部。我们希望它记住的那一部分，足够准确，也足够谦逊。
